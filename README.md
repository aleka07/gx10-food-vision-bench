# gx10-food-vision-bench

Измерение локального вывода моделей компьютерного зрения на платформе ARM64 с GPU NVIDIA GB10
(ASUS Ascent GX10) для задач пищевой промышленности: задержка, пропускная способность и
энергопотребление. Код, конфигурации и первичные данные к статье «Локальный вывод моделей
компьютерного зрения на ARM64-платформе с GPU GB10: задержка, пропускная способность и
энергопотребление» (МНПК АТУ, Алматы, 22.10.2026).

## Что измерено

| Что | Как |
|---|---|
| Модели | ResNet-50 (IMAGENET1K_V2), ConvNeXt-Tiny (IMAGENET1K_V1), ViT-B/16 (IMAGENET1K_V1) — веса torchvision |
| Данные | Food-101 (CC BY 4.0), 101 класс: 5050 изображений для зонда (50/класс), 2525 для оценки (25/класс) |
| Адаптация | линейный зонд на замороженных признаках, гребневая регрессия в замкнутой форме |
| Режимы вывода | `inference_only` (батч уже на устройстве) и `end_to_end` (JPEG-декодирование и resize на CPU, передача в GPU) |
| Точность | CPU FP32 (20 потоков), GPU FP32 / FP16 / BF16 |
| Батчи | 1, 8, 32 |
| Повторы | 3 на конфигурацию, в отчётах медиана |
| Энергия | NVML `power.draw` каждые 20 мс, интегрирование по окну измерения; фон в простое 4,9 Вт |

| Параметр | Значение |

## Воспроизведение

```bash
python3 -m venv .venv
.venv/bin/pip install torch==2.14.0 torchvision==0.29.0 --index-url https://download.pytorch.org/whl/cu130
.venv/bin/pip install -r requirements.txt

# все 11 шардов датасета (около 5 ГБ); Xet отключён: на стенде его read-token отдавал 404
HF_HUB_DISABLE_XET=1 .venv/bin/python scripts/download_food101.py
.venv/bin/python src/data_food101.py --per-class 50 --eval-per-class 25

cd src
../.venv/bin/python run_all.py --stage features probe --probe-per-class 5 10 25 50
for s in 42 43 44; do for b in resnet50 convnext_tiny vit_b_16; do
  ../.venv/bin/python probe.py --features ../results/features_$b.npz \
    --out ../results/probe_seeds/${b}_s$s.json --per-class 5 10 25 50 --seed $s; done; done
../.venv/bin/python bench.py --min-images 128 --min-duration 2.0 --repeats 3
../.venv/bin/python figures.py
../.venv/bin/python analyze.py      # печатает таблицы статьи и пишет results/summary.{json,csv,md}
```

Разбор датасета: шарды Food-101 отсортированы по классам, поэтому для полного покрытия 101 класса
нужны все 8 обучающих и все 3 валидационных шарда. В репозитории Hugging Face официальный
тестовый набор (25 250 изображений) лежит в каталоге `validation`, что и отражено в манифесте.

## История протокола

Первая версия харнесса дала недостоверную энергию: измерение начиналось вместе с запуском
сэмплера мощности, поэтому для коротких конфигураций первые пробы NVML приходились на простой
модуля (7,2 Вт против 23,5 Вт на одинаковых прогонах одного и того же варианта). Протокол
исправлен: нагрузочный прогрев не менее 1 с перед окном, окно измерения не короче 2 с, сэмплер
запускается до прогрева. Прежний файл оставлен для сверки —
`results/bench_raw_v1_shortwindow.json`; в статье используются только данные исправленного
протокола.

## Ограничения

Измерена классификация, а не детекция дефектов. Использованы один стенд и один набор данных.
Квантование INT8 и TensorRT не рассматривались. Мощность измерена на уровне модуля: датчик NVML
охватывает SoC и память, отдельного счётчика процессора нет, поэтому энергия отнесена к
платформе, а не к ускорителю. Показатель «45 потоков по 30 кадров/с» — арифметическая оценка
исходя из измеренной пропускной способности, а не результат многокамерного эксперимента.
